# 发布准备与接入说明

## 为什么

包做出来以后，要能一次把两个语言的包以同一个版本发出去，使用方也要知道怎么用。本条把这两件事准备到「维护者一决定就能发、使用方照着说明就能接」的程度。

## 交付

1. 发布流程：npm 包与 Python 包从同一个提交构建并上传，版本号一致。
2. 一次本机构建演练的记录（不上传）。
3. README：这套结构是什么、各语言怎么引入和使用、版本与兼容规则。

## README 要写到的内容

- 每个结构一小段：长什么样、什么时候用、一个最小例子。
- 三种列表怎么选。
- 业务码：通用码有哪些、专有码怎么加、遇到不认识的码怎么处理。
- TS：怎么安装、怎么引入类型与常量、怎么拿到定义文件自己做校验。
- Python：怎么安装、怎么用模型声明接口的返回类型。
- 版本规则：什么算破坏性改动（改名、删字段、收紧取值范围、给开放字段加枚举限制），破坏性改动升主版本。
- 本包不做什么：不带定制开关；后端不按这套结构的项目不引本包，在自己的请求层适配。

README 只讲本包自己，不写任何具体使用方的名字。

## 怎么算完成

- 发布流程里有版本一致检查，且 Python 包的步骤在文件里写全；演练记录写明两个包的文件清单与版本号。
- README 的接入步骤在一个空目录里照做能走通（TS 一次、Python 一次），用本机构建产物安装。

## 自己定与不能动

- 自己定：发布流程的具体写法、README 的组织。
- **不发布、不 push。** 流程写好即可；凭据的配置方式只写说明，不读、不打印任何凭据。
- 本仓公开：文档、提交说明与流程文件里不写不公开的项目名、内部路径或内部决策编号。

## 上报条件

- 发布流程需要用户提供账号或在托管平台上做配置。
